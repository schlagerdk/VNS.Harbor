    Add environment
    
    
    
    
    Where does it run?
    
    
    
      
      
      
    
    
    
    Site
    
    
    
      
      
      
      
    
    
    
    
    
    
      
    SSH connection
    
      
    
        
        
        
        
      
    
      
    A password is optional when SSH keys are configured. If provided, it is saved in this site's root-only production script. If /var/www/<folder> on the server already holds this site, it is adopted as it is: its binding, protocol and environment are read from the server, and nothing is published or changed there.
    
    
    
    
    
      
    Windows connection (SMB)
    
      
      
    
        
        
        
      
    
      
    
      
    The IIS site's folder is the share and the folder name, like /var/www/<folder> on Linux. The IIS site and its folder must already exist, with the ASP.NET Core Hosting Bundle and IIS URL Rewrite Module installed. web.config is created on the first publish, with the HTTPS redirect and Umbraco's sitemap and robots rewrites when they apply. If the share already holds this site, it is adopted as it is: its environment is read from its web.config, and nothing is published or changed there. The password is saved in this site's root-only production scripts.
    
    
    
    
    
      
    Local folder
    
      
      
    
    
    
    
    The environment becomes a separate site again, in the folder it already has. Its files, service and Apache config are not touched, and it can no longer be published from this site until it is moved back.
    
    
    
    
    
      
      
      
    
        SQL connection
        
    The database and login must already exist. No SQL database or login is created.
    
        
    
          
          
          
          
        
    
      
    
    
    
    
    
      
    The site is stopped while the whole folder is copied, including its build, media, logs and a SQLite database, so it runs the same version afterwards. To Windows only settings and content are copied, and it is built there. A SQLite database goes with the files. A database in SQL Server stays where it is: a connection to the old server's own SQL Server is changed to that server's IP, and it must accept connections from the new server. With HTTPS, DNS must already point to the new server. If a step fails, the site keeps running where it is.
    
      
    
    
    
  
    
    


  
    
    
    
      ↳
      
    Move under main site
    
    
    
    
    
    The site becomes an environment of the main site, which publishes to it from now on. Its files, service and Apache config stay where they are and it keeps running. Nothing is published now. Only main sites that build the dll this site runs are listed. You can move it out again.
    
    
  
    
    


  
    
    
    
      
      
    Sync settings
    
    
    
    
    From
    
    
    
      Sync to 
      
    
    
    
    
    The uSync settings (document types, data types, templates, languages and the like), Views, css and scripts are mirrored. Content, media, dictionary and domains are never touched. A folder that is missing in the source is skipped.
    
    
    Settings are first synced from the main site to the destination. Then content and media are merged into it: they are added and updated, never deleted. The destination restarts, and uSync imports the data at startup.

    Turn everything off to keep the site out of sync altogether. Saving sets uSync in this site's appsettings.json and restarts the site when it changes: the content and media handlers by what it takes part with, export on save when it can send, and import at startup when it can receive. Data syncs between two sites when the source can send, the destination can receive, and only what both take part with. Domains are never synced.
